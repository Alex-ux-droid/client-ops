# client-ops

Особиста веб-система-офіс для одного користувача (Саша): ведення клієнтів (Facebook-реклама, сайти, налаштування відділів продажу: CRM, телефонія, навчання). Мета: економія часу. Все, що Саша тримає в голові по клієнтах, тут: потреби, бюджети, бачення клієнта і своє, задачі, історія робіт, ідеї, матеріали (чати, дані з реклами), плейбуки. Помічник (ШІ) пам'ятає історію клієнта і допомагає із задачами.

## Як спілкуватись із Сашею
- Українською, неформально, на «ти». Коротко, простою мовою, без важких термінів.
- Чесно про слабкі місця. Не вигадувати; якщо не впевнений, спитати.
- Технічні дрібниці вирішувати самому, Сашу питати тільки про те, що впливає на роботу.

## Стек
- Next.js 16 (App Router, TypeScript), server components + server actions.
- SQLite через `better-sqlite3`, голі SQL-міграції в `db/migrations/*.sql` (без ORM).
- PWA (manifest + service worker) — окремий етап.
- Помічник: `@anthropic-ai/sdk` (Messages API + свій цикл інструментів, `lib/agent/`). Модель, effort і власні інструкції Саша міняє на сторінці «Налаштування» (таблиця `settings`, `lib/agent/config.ts`); за замовчуванням `claude-sonnet-5-5`, effort `medium`. `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) тільки для моделей, що його підтримують. Agent SDK не взяли: він тягне рушій Claude Code з файловими/bash-інструментами, а тут потрібні тільки інструменти бази. API перевіряти в документації, не вгадувати.
- Ключ API вводиться на сторінці «Налаштування» і дописується в `.env` на сервері (`lib/secrets.ts`). План Max НЕ покриває API — оплата з кредитів у platform.claude.com.
- Помічник доступний з будь-якої сторінки (`Shell` → панель з `Chat compact`); на сторінці клієнта — розмова цього клієнта. Голос — `components/useDictation.ts` (браузерне розпізнавання, текст іде в поле, Саша сам натискає «Надіслати»).
- Історія чату між ходами зберігається тільки текстом (без thinking-блоків), всередині ходу — повний вміст відповідей без змін (append-only).
- Стилі: один `app/globals.css` з CSS-змінними (дизайн-токени). Без UI-бібліотек.

## Структура
- `db/migrations/` — схема. Нова зміна = новий файл `00N_*.sql`, старі не редагувати.
- `lib/db.ts` — з'єднання; `lib/migrate.mjs` — міграції (спільні з `scripts/`).
- `lib/repo/*` — ВЕСЬ доступ до БД тільки тут.
- `lib/session.ts` — підпис/перевірка сесії; `lib/auth.ts` — `requireUser()`; `proxy.ts` — захист сторінок; `app/login/` — вхід.
- `app/actions.ts` — усі server actions; сторінки в `app/`; спільні шматки в `components/` (`Shell` — меню/пошук/швидке додавання, `Charts` — SVG-графіки без бібліотек).
- `lib/config.ts` — валюта (`APP_CURRENCY`, одна на всю систему) і `money()`.
- Пошук: SQLite LIKE не знає регістр кирилиці — використовувати `ulower()` (реєструється в `lib/db.ts`).
- `scripts/seed.mjs` — тестові дані.

Команди: `npm run dev`, `npm run typecheck`, `npm run build`, `npm run db:seed`, `npm run db:reset`.

## Жорсткі правила
- ПАРОЛІ В БАЗІ НЕ ЗБЕРІГАТИ. Тільки текстове посилання на запис у Bitwarden (`bitwarden_ref`).
- Ключі тільки в `.env` (у `.gitignore`). `.env.example` з пустими значеннями. Нічого секретного в коміти.
- У базі тільки тестові seed-дані, жодних реальних клієнтів у репо. `data/` в `.gitignore`.
- Вхід за одним паролем (`APP_PASSWORD`), сесія — підписана кука (`SESSION_SECRET`). `proxy.ts` закриває всі сторінки, `requireUser()` перевіряє кожен server action. Локально без `APP_PASSWORD` вхід вимкнено; на проді без нього все закрито.
- Мінімум залежностей, простий код. Мобільний UI в першу чергу.
- Працювати етапами, після кожного етапу коміт з нормальним повідомленням.

## Як Claude перевіряє прод
- Ключ доступу для Claude (`AGENT_TOKEN` у `.env` на сервері) Саша генерує в «Налаштуваннях». У хмарному середовищі він лежить у змінній `CLIENT_OPS_TOKEN`, домен `2-28-114-219.sslip.io` дозволений у мережі середовища.
- Стан: `curl -s -H "Authorization: Bearer $CLIENT_OPS_TOKEN" https://2-28-114-219.sslip.io/api/status` — коміт, міграції, кількість записів, налаштування помічника, лог оновлень, останні помилки.
- Сторінки: Playwright з `extraHTTPHeaders: { Authorization: "Bearer ..." }`. Там РЕАЛЬНІ дані клієнтів — нічого не змінювати і не копіювати в репо без прохання Саші.

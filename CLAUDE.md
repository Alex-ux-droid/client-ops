# client-ops

Особиста веб-система-офіс для одного користувача (Саша): ведення клієнтів (Facebook-реклама, сайти, налаштування відділів продажу: CRM, телефонія, навчання). Мета: економія часу. Все, що Саша тримає в голові по клієнтах, тут: потреби, бюджети, бачення клієнта і своє, задачі, історія робіт, ідеї, матеріали (чати, дані з реклами), плейбуки. Помічник (ШІ) пам'ятає історію клієнта і допомагає із задачами.

## Як спілкуватись із Сашею
- Українською, неформально, на «ти». Коротко, простою мовою, без важких термінів.
- Чесно про слабкі місця. Не вигадувати; якщо не впевнений, спитати.
- Технічні дрібниці вирішувати самому, Сашу питати тільки про те, що впливає на роботу.
- Після роботи — ТІЛЬКИ короткий підсумок тезами (3–6 пунктів по рядку): що зроблено, що зробити Саші, слабке місце. Без абзаців, пояснень і довгих списків. Детально — лише коли Саша прямо просить.

## Стек
- Next.js 16 (App Router, TypeScript), server components + server actions.
- SQLite через `better-sqlite3`, голі SQL-міграції в `db/migrations/*.sql` (без ORM).
- PWA: manifest + service worker. SW НЕ кешує сторінки і API (там дані клієнтів) — лише `/_next/static` та іконки. При зміні sw.js міняти `CACHE`.
- Помічник: `@anthropic-ai/sdk` (Messages API + свій цикл інструментів, `lib/agent/`). Модель, effort і власні інструкції Саша міняє на сторінці «Налаштування» (таблиця `settings`, `lib/agent/config.ts`); за замовчуванням `claude-sonnet-5-5`, effort `medium`. `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) тільки для моделей, що його підтримують. Agent SDK не взяли: він тягне рушій Claude Code з файловими/bash-інструментами, а тут потрібні тільки інструменти бази. API перевіряти в документації, не вгадувати.
- Ключ API вводиться на сторінці «Налаштування» і дописується в `.env` на сервері (`lib/secrets.ts`). План Max НЕ покриває API — оплата з кредитів у platform.claude.com.
- Помічник ОДИН, звати Джері (ім'я в UI і в SYSTEM) — робот-віконце (`Shell` → `Chat compact`), окремої сторінки/вкладок помічника нема (`/assistant` → редірект). На сторінці клієнта — розмова цього клієнта. З кожним повідомленням іде текст екрана (`screenText()` у `Chat.tsx`: адреса, заголовок, вкладка, текст `main` до 3200 симв.) → блок `<screen>` у контексті, щоб «це/тут» розумілось без пояснень. Персонаж-робот `components/Bot.tsx` (SVG, стани idle/listening/thinking) завжди на екрані: на компʼютері в правому нижньому куті, на телефоні — центральна кнопка нижнього меню; чат відкривається віконцем. Робот: короткий тап — чат, затиснув — запис голосу, відпустив — текст іде Джері (`useHoldToTalk.ts`, підказка `.ptt-toast`). Будь-яка сторінка може відкрити помічника з текстом: `openAssistant(text, send)` з `components/assistant.ts`. Голос — `components/useDictation.ts` (браузерне розпізнавання; кожне натискання = окрема сесія, текст іде в поле на «стоп», Саша сам натискає «Надіслати»). Озвучка відповідей — `components/useSpeech.ts` (кнопка «Голос» у чаті, вибір у localStorage). Якщо підключено ElevenLabs (Налаштування → Конектори → ElevenLabs; `lib/voice.ts`, ключ `ELEVENLABS_API_KEY` у .env, голос/модель у settings `voice.*`): диктування = запис MediaRecorder → `/api/stt` (Scribe: `scribe_v2`, запасний `scribe_v1`, мова uk), голос = `/api/tts` (mp3), на iPhone плеєр «розблоковується» тишею під час натискання. Без ElevenLabs — вбудовані розпізнавання і голос браузера. Диктування як у Claude: поки говориш — почуте сірим поверх поля (`DictOverlay.tsx`, поле під ним `vt-ghost`), на «стоп» `useDictation.finalize` → `/api/stt/fix` (`lib/dictFix.ts`, claude-haiku-5-5: розділові знаки + власні назви зі словника `lib/repo/vocab.ts` — клієнти, стартапи, інструменти, кабінети, групи + settings `voice.vocab`; тумблер `auto.dict_fix`; при помилці — сирий текст) → текст у поле. Офіційну документацію ElevenLabs з хмарної сесії не відкрити (мережа) — формат узято з пошуку, перевірено тільки на заглушці.
- Помічник = права рука: роль і місія в `SYSTEM` (`lib/agent/run.ts`), повний доступ (створити/змінити/архівувати/видалити; `delete_client` тільки з точною назвою), пам'ять `agent.memory` (memory_add / memory_rewrite, редагується в Налаштування → Помічник) — підставляється в системний промпт. Після кожної розмови `lib/agent/reflect.ts` у фоні перечитує обмін і переписує пам'ять по розділах (Про Сашу / Як працювати / Помилки й уроки / Цілі / Поточний фокус) або NO_CHANGE.
- Чат Джері: на компʼютері розгортається на весь екран (`Shell` → `full`, localStorage `dock.full`); «+» у полі (`Chat.tsx`): вкладення (`components/chatFiles.ts` — фото стискаються до 1600px, PDF, текст; також Ctrl+V і перетягування) → `/api/chat` `files` → `runAgent(..., files)` → image/document блоки в повідомленні (в історію йдуть лише назви); тумблери web / context (`/api/chat/prefs`) і голос; «Нова розмова».
- Контекст без «подивись» (`lib/agent/context.ts`, тумблер `auto.context`): Chat шле `taskId` (відкрита задача або закрита ≤20 хв — `html[data-task]` з TaskModal) → `contextBlock` додає `<task>` (галочки, інструкція, посилання) і `<client>` — знімок клієнта: Meta (кабінет, 7 проти 7 днів, кампанії/групи/креативи з ad_id і цифрами, тривоги, розбір), заявки з лід-форм за 7 днів, гроші, профіль спілкування, задачі в роботі.
- Історія чату між ходами зберігається тільки текстом (без thinking-блоків), всередині ходу — повний вміст відповідей без змін (append-only).
- Стилі: один `app/globals.css` з CSS-змінними (дизайн-токени). Без UI-бібліотек.

## Структура
- `db/migrations/` — схема. Нова зміна = новий файл `00N_*.sql`, старі не редагувати.
- `lib/db.ts` — з'єднання; `lib/migrate.mjs` — міграції (спільні з `scripts/`).
- `lib/repo/*` — ВЕСЬ доступ до БД тільки тут.
- `lib/session.ts` — підпис/перевірка сесії; `lib/auth.ts` — `requireUser()`; `proxy.ts` — захист сторінок; `app/login/` — вхід.
- `app/actions.ts` — усі server actions; сторінки в `app/`; спільні шматки в `components/` (`Shell` — меню/пошук/швидке додавання, `Icon` — SVG-іконки в стилі Lucide, `Charts` — SVG-графіки без бібліотек).
- `app/clients/[id]/` — хаб клієнта: `layout.tsx` + `ClientNav.tsx` (на компʼютері ліва панель замінюється «картою» клієнта; розділи — `sections.ts`, Пошта тільки якщо в клієнта є email), `page.tsx` (шапка; вкладки лише на телефоні), `Overview.tsx` (зведення: де ми, куди йдемо, гроші, у роботі, зроблено, Telegram, ідеї), `SetupTab.tsx` (послуги, дані, звʼязок), `ServiceTab.tsx`, `FilesTab.tsx`, `tabs.tsx` (задачі, історія, гроші, матеріали, плейбуки, цифри реклами).
- `lib/config.ts` — валюта (`APP_CURRENCY`, одна на всю систему) і `money()`.
- Пошук: SQLite LIKE не знає регістр кирилиці — використовувати `ulower()` (реєструється в `lib/db.ts`).
- `scripts/seed.mjs` — тестові дані.

Команди: `npm run dev`, `npm run typecheck`, `npm run build`, `npm run db:seed`, `npm run db:reset`.

## Жорсткі правила
- ПАРОЛІ В БАЗІ НЕ ЗБЕРІГАТИ. Тільки текстове посилання на запис у Bitwarden (`bitwarden_ref`).
- Ключі тільки в `.env` (у `.gitignore`). `.env.example` з пустими значеннями. Нічого секретного в коміти.
- У базі тільки тестові seed-дані, жодних реальних клієнтів у репо. `data/` в `.gitignore`.
- Вхід за одним паролем (`APP_PASSWORD`) + підтвердження в Telegram, сесія — підписана кука (`SESSION_SECRET` + `SESSION_EPOCH`). Кука `термін.режим.підпис`: `r` — «Запамʼятати пристрій» (7 днів), `i` — без галочки: 30 хв, `proxy.ts` продовжує на кожен запит, кука без maxAge; `components/SessionGuard.tsx` у Shell — 30 хв без дій → `/login`, пінг `/api/ping` раз на 4 хв при активності. `proxy.ts` закриває всі сторінки, `requireUser()` перевіряє кожен server action. Локально без `APP_PASSWORD` вхід вимкнено; на проді без нього все закрито.
- Мінімум залежностей, простий код. Мобільний UI в першу чергу.
- Працювати етапами, після кожного етапу коміт з нормальним повідомленням.
- Налаштування → «Можливості» (`lib/agent/caps.ts`): тумблери що Джері може (`CAPS` → групи інструментів; вимкнене прибирається з `tools` і блокується в `runTool`, Джері каже де увімкнути) і що система робить сама (`AUTO`: зведення, тижневий розбір, бекап, фото з Telegram на Диск, самонавчання). ПРАВИЛО: кожна нова можливість Джері чи фонова автоматика — одразу свій тумблер тут; коли сумніваєшся, чи Саші це треба, — роби тумблером, а не питай.
- Журнал оновлень (`changelog`, міграція 015, Журнал → «Оновлення», `lib/repo/changelog.ts`): після КОЖНОЇ помітної зміни для Саші — новий файл міграції з `INSERT INTO changelog (title, body)` простими словами (що додали, як користуватись, обмеження). Останні 8 записів ідуть Джері в системний промпт (`updatesBlock` у `lib/agent/run.ts`), повний список — інструмент `system_updates`. Без цього Джері не знає про нові можливості і тримається старої пам'яті.

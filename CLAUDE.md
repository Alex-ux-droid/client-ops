# client-ops

Особиста веб-система-офіс для одного користувача (Саша): ведення клієнтів (Facebook-реклама, сайти, налаштування відділів продажу: CRM, телефонія, навчання). Мета: економія часу. Все, що Саша тримає в голові по клієнтах, тут: потреби, бюджети, бачення клієнта і своє, задачі, історія робіт, ідеї, матеріали (чати, дані з реклами), плейбуки. Помічник (ШІ) пам'ятає історію клієнта і допомагає із задачами.

## Як спілкуватись із Сашею
- Українською, неформально, на «ти». Коротко, простою мовою, без важких термінів.
- Чесно про слабкі місця. Не вигадувати; якщо не впевнений, спитати.
- Технічні дрібниці вирішувати самому, Сашу питати тільки про те, що впливає на роботу.

## Стек
- Next.js 16 (App Router, TypeScript), server components + server actions.
- SQLite через `better-sqlite3`, голі SQL-міграції в `db/migrations/*.sql` (без ORM).
- PWA (manifest + service worker) — окремий етап.
- Помічник: Claude. Модель у `.env` (`AGENT_MODEL`), за замовчуванням Sonnet. Пакет вибрати на етапі чату (`@anthropic-ai/claude-agent-sdk` або простіший `@anthropic-ai/sdk`), API перевіряти в документації, не вгадувати.
- Стилі: один `app/globals.css` з CSS-змінними (дизайн-токени). Без UI-бібліотек.

## Структура
- `db/migrations/` — схема. Нова зміна = новий файл `00N_*.sql`, старі не редагувати.
- `lib/db.ts` — з'єднання; `lib/migrate.mjs` — міграції (спільні з `scripts/`).
- `lib/repo/*` — ВЕСЬ доступ до БД тільки тут.
- `lib/session.ts` — підпис/перевірка сесії; `lib/auth.ts` — `requireUser()`; `proxy.ts` — захист сторінок; `app/login/` — вхід.
- `app/actions.ts` — усі server actions; сторінки в `app/`; спільні шматки в `components/`.
- `scripts/seed.mjs` — тестові дані.

Команди: `npm run dev`, `npm run typecheck`, `npm run build`, `npm run db:seed`, `npm run db:reset`.

## Жорсткі правила
- ПАРОЛІ В БАЗІ НЕ ЗБЕРІГАТИ. Тільки текстове посилання на запис у Bitwarden (`bitwarden_ref`).
- Ключі тільки в `.env` (у `.gitignore`). `.env.example` з пустими значеннями. Нічого секретного в коміти.
- У базі тільки тестові seed-дані, жодних реальних клієнтів у репо. `data/` в `.gitignore`.
- Вхід за одним паролем (`APP_PASSWORD`), сесія — підписана кука (`SESSION_SECRET`). `proxy.ts` закриває всі сторінки, `requireUser()` перевіряє кожен server action. Локально без `APP_PASSWORD` вхід вимкнено; на проді без нього все закрито.
- Мінімум залежностей, простий код. Мобільний UI в першу чергу.
- Працювати етапами, після кожного етапу коміт з нормальним повідомленням.
